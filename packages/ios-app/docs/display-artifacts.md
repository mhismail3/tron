# Display artifacts

Tron's reserved first-party `display` tool presents agent-selected project artifacts and public HTTPS references without making native UI an extension-owned capability. Canonical Pi JSONL records one ordinary `tron.display.v1` tool result; Gateway artifact bytes are immutable durable sidecars; every iOS value is a bounded disposable projection.

The Gateway also accepts `source: { kind: "internal_file", path: "reports/summary.md" }`
for visible files beneath Tron's internal `workspace/files`, independent of the
session cwd. Ordinary `path` sources remain session-relative. Both produce the
same immutable authenticated artifact and `tron.display.v1` projection; iOS does
not browse, cache, or mirror the internal workspace. Missing/unavailable roots,
managed-state paths, traversal, hidden components, and symlinks are rejected by
the Gateway before presentation.

## Live browser views

A trusted `agent_browser` `get cdp-url` result can supply an opaque `browser_live` source to `display`. iOS requires the authenticated `browser-live-view.v1` capability before opening it. Only an active sheet or eligible, genuinely visible floating panel mounts a viewer; retained pills/history do no capture, delivery or decoding. Existing floating-completion admission and sticky dismissal behavior remain unchanged. The sheet has a native Close control; reopening never launches a browser and can attach only to the original still-live generation.

`BrowserLiveDisplayView` keys its task by the exact display, session, profile, scene and managed presentation activity. It fences admission/publication with the current application state and mutable managed-surface owner, plus cancellation, exact surface generation, profile and latest-request nonce; it does not rely solely on SwiftUI task cancellation timing. Dismissal, coverage, backgrounding and profile/session replacement retire presentation work. `BrowserLiveLease` carries the **original** origin/credential and owns one joined, cancellation-independent DELETE task. Cancellation initiates cleanup without waiting for an in-flight native decode to finish; duplicate closes join it and late frame responses are rejected. Changing profiles cannot strand cleanup or send the old lease to a new Gateway. The live transport follows no redirects. Network/process loss still requires the Gateway's fifteen-second idle lease expiry (with up to one additional second for sweeping); no instantaneous remote cleanup is claimed offline.

Polling is sequential and capped at five requests per second. `X-Tron-Live-After` avoids retransmitting unchanged JPEGs; `waiting` clears previous-target pixels, while `unchanged` retains an already decoded frame. Ended observation is a terminal error rather than an automatic reconnect loop. `BrowserLiveFrame` admits at most 2 MiB JPEG data, checks the encoded image's own dimensions against response metadata before decoding, then uses off-main, cancellation-fenced ImageIO preparation with a four-million-pixel, 2,560-edge and 16-million-decoded-byte limit. One app-wide preparation slot includes retired viewer generations: an already-running synchronous ImageIO call may drain after cancellation, but replacement candidates are dropped rather than queued or decoded concurrently. There is no image queue or artifact-cache insertion.

The typed descriptor contains no CDP URL, host path, browser port or input channel. Ordinary browser-tool diagnostics remain ordinary owner-authenticated tool output, not transport authority. Gateway owns only the read-only observer; browser automation continues independently. Child live-view handoff and native-daemon crash cleanup are not certified by this first-party feature. Focused coverage: `BrowserLiveViewingTests` checks original-profile cleanup, late open/frame fencing, capability, actual JPEG admission, non-cancellable preparation overlap and independent frame decodes using the production shared owner. `BrowserLiveMountedViewingTests` checks direct `DisplaySheet` polling/coverage, retained-host quiescence, dismissal, same-identity generation/profile replacement and joined lease/surface teardown even when the fixture throws. `DisplayPresentationTests` covers wire/surface/auto-presentation policy; Gateway regressions cover loader, lease and HTTP authority. The mounted harness uses injected transport and a hosted `UIWindow`; it does not certify real chat item-sheet routing, floating gestures, OS suspension or physical-device rendering.

## Surfaces

The model requests a surface, but native policy resolves it by typed content kind and advertised eligibility:

- **Sheet** is the default and universal fallback. The running pill settles to a completed pill; an explicit tap opens the centrally routed `DisplaySheet`.
- **Inline** keeps the tool call's physical row identity. Its running pill and collapsed result share the normal left transcript edge. Textual content expands into a nearly full-width, rounded lavender Liquid Glass container with an adaptive bounded viewport and no nested transcript scroll. Images instead use a left-aligned 1.7× photo chip with an inset close control and a color-scheme-adaptive backing for transparent pixels; tapping the photo opens the canonical photo sheet and closing morphs back to the tool pill. One measured row host keeps both endpoints mounted without any clipping surface. Collapse first fades the card and its native shadow at the expanded height, then contracts the already-invisible card region into the visible pill; expansion grows and crossfades in one transaction. The stable host prevents structural rerender glitches while preserving the same natural rounded Liquid Glass shadow as a user-message bubble. Disclosure state reaches its stable endpoint synchronously; backgrounding, presentation coverage, route removal, and retained resume therefore cannot inherit an in-flight logical phase. While the transcript is positioning, an expanded display keeps a bounded kind-specific placeholder and does not mount its asynchronous artifact renderer; adaptive content begins only after the opening reveal and physical tail lease have fully settled, when native pinned anchoring owns subsequent height changes. Public web, HLS, generic documents, and interactive HTML do not become inline scroll children.
- **Floating** keeps the completed pill and may publish one session-local overlay after an eligible live completion. The panel is one rounded Liquid Glass window without a solid header bar. Compact glass handle, close, and expand controls retain 44-point accessibility targets; handle dragging tracks directly, projects release velocity, snaps smoothly to the nearest horizontal edge, and remains clamped from the toolbar down to the measured composer boundary. It is recoverable by tapping the canonical pill and is not a second `UIWindow` or system Picture in Picture.

Unsupported requested surfaces deterministically fall back to sheet. Audio/video larger than 50 MiB cannot trigger automatic inline or floating download; when floating was requested, an explicit user tap may open the bounded staged-file panel. The agent cannot choose dimensions, coordinates, z-order, autoplay, permissions, or whether close controls exist.

## Ownership and lifecycle

`ChatTranscriptProjectionKernel` keeps a display invocation in an isolated one-tool run so generic neighboring tools never morph with it. `ChatToolDescriptor` carries the strictly decoded display projection and the bounded requested surface needed by the running pill. Live-to-canonical reconciliation retains the tool-call physical identity and canonical result wins.

`ChatRoutes` owns the display sheet. `ChatSessionPresentation` owns only disposable selected-sheet, one floating route, one deferred floating route, and a bounded exact-revision auto-presentation ledger. `ChatFloatingDisplayHost` is mounted over the chat content surface rather than inside the transcript scroll view. Closing, dragging, collapsing, and maximizing do not mutate Gateway or JSONL.

A floating panel appears automatically only for a completion added after the current installed-transcript baseline while the exact chat is ready, foreground-active, presentation publication is allowed, and no panel is already user-owned. The baseline resets rather than publishing when history or reconnect installs a transcript, so cache installation, foreground restoration, and background completion retain only the pill. A covering descendant may defer one candidate; route retirement clears all display presentation state.

## Rendering and security

Every display includes alt/fallback text and every renderer publishes that description to accessibility. Artifact requests use the selected profile plus exact session and opaque artifact identity. Markdown, text, code, PDF, and document sheets reuse `AttachmentFilePreviewSheet` and its `TronDocumentSheet` chrome while preserving the display's authored title. Document content leaves its background transparent so the native sheet material matches other standard sheets in both appearances; PDF pages retain their paper color, but their surrounding viewport is clear. The concrete document scroll owner supplies the custom top blur; native navigation and bottom-toolbar backgrounds stay hidden instead of adding solid bars. The same transparent shell applies to question/form, terminal, and unavailable-queue sheets (terminal/media content retains its own rendering). `SessionSheetPresentationTests` compares document background paint against a native sheet (with an opaque-background negative control) and exercises the scrolled Markdown reader in both appearances. Image sheets reuse the exact historical photo-chip sheet—including its medium detent, concentric viewport, native pinch/double-tap zoom, overlay title, and glass confirmation control—while loading through `ChatMediaLoader`; local photo chips keep the thumbnail only as immediate presentation input and propagate the decoded full-resolution replacement into the mounted zoom view instead of trapping that thumbnail in sheet-local state. Inline images keep their bounded transcript renderer. Inline PDFs and bounded text also reuse existing native preview preparation, while unsupported generic documents stay sheet-only. Local audio/video is downloaded through the authenticated bounded file transport, validated against its advertised size, played from protected temporary storage without autoplay, and discarded on cancellation or teardown. Public webpage/HLS descriptors reject credentials, query/fragment persistence, private/reserved literals, and local DNS suffixes, then open as full-height, full-bleed `SFSafariViewController` sheets with one collapsible native browser bar and no duplicate Tron navigation chrome. Safari's close control dismisses the owning sheet, and Gateway credentials are never attached to remote redirects, playlists, segments, or keys.

Generated HTML uses a nonpersistent `WKWebView`, disabled JavaScript, no base URL or file access, user-action media policy, blocked popup creation, navigation restricted to `about`, and a strict CSP that disables network, forms, frames, and script. SVG is classified with active HTML rather than inert image decoding. Renderer failure preserves the canonical fallback instead of hiding the transcript item.

Inline rendering is lazy and bounded. Text/PDF payloads retain the existing 25 MiB encoded boundary and preparation limits. Images cap decoded dimensions through `ChatMediaLoader`. Media teardown pauses and clears AVFoundation state before deleting its staged file. Floating content is session-local and is retired on background or route teardown.

## Accessibility

Display pills remain one compact control with their destination in the accessibility label. Inline content has separate 44-point collapse and optional sheet controls. Floating panels expose close/maximize controls and named corner movement actions so drag is never the only input. Agent-opened floating content does not intentionally move VoiceOver focus. Reduce Motion replaces scale/geometry transitions with short fades.
