# Display artifacts

Tron's reserved first-party `display` tool presents agent-selected project artifacts and public HTTPS references without making native UI an extension-owned capability. Canonical Pi JSONL records one ordinary `tron.display.v1` tool result; Gateway artifact bytes are immutable durable sidecars; every iOS value is a bounded disposable projection.

The Gateway also accepts `source: { kind: "internal_file", path: "reports/summary.md" }`
for visible files beneath Tron's internal `workspace/files`, independent of the
session cwd. Ordinary `path` sources remain session-relative. Both produce the
same immutable authenticated artifact and `tron.display.v1` projection; iOS does
not browse, cache, or mirror the internal workspace. Missing/unavailable roots,
managed-state paths, traversal, hidden components, and symlinks are rejected by
the Gateway before presentation.

## Live browser and native Mac views

A trusted `agent_browser` `get cdp-url` result can supply an opaque `browser_live` source to `display`. iOS requires the authenticated `browser-live-view.v1` capability before opening it. Only an active sheet or eligible, genuinely visible floating panel mounts a viewer; retained pills/history do no capture, delivery or decoding. Live browsers default to a floating panel with aspect-fit content. Before the first admitted renderable frame it uses the 4:3 fallback; afterward the existing floating host fits each admitted frame's validated dimensions (including portrait, landscape and extreme ratios) to its native available container while retaining standard close/expand controls and exact source identity across action/display chips. Expanding uses themed Tron title/Done chrome, starts at the medium detent, permits medium/large detents and hides the drag indicator. The covered floating owner stops viewing and shows a centered popped-out icon until the exact managed sheet retires. This visual state comes from the presentation coordinator's mounted descendant topology, not a second flag or the sheet binding (which may clear before native dismissal finishes). Later actions do not reopen a manually dismissed browser; an explicit chip tap does. Closed-browser results remain manually inspectable but do not automatically open an unavailable panel. Reopening never launches a browser and can attach only to the original still-live generation. Actual 1024×768 browser-content defaults belong to the native provider's local-launch initialization, not the phone's panel layout; explicit window/viewport controls and attached browsers are not reset by viewing.

Native whole-display, window and display-region references enter through `display` as `native_live`, with `liveView.schema: tron.native-live-view.v1` and the same bounded `viewId`, `generation`, `title` and `fallbackText` fields. They require `native-live-view.v1`; browser descriptors and `browser-live-view.v1` remain distinct, unchanged contracts. Display kind must match the descriptor schema both at transcript decode and HTTP lease admission. Presentation identity includes the producer (`native:` versus the unchanged `browser:` prefix), so identical opaque IDs cannot inherit another producer's dismissal, pixels or geometry. `native_capture` returns an opaque reference, not an admitted display projection; its raw tool details never mount a renderer.

Both producers use the **same** `LiveDisplayView`, `LiveLease`, `/v1/sessions/:sessionId/live-views/:viewId` POST/frame/DELETE transport and JPEG headers. Native views use the existing floating/sheet renderer, aspect-fit frame geometry, fallback ratio, controls and managed presentation fences described here; they add no capture work for hidden pills, history installation or reconnect. Last-viewer retirement suspends and joins the native stream, while the Host retains the exact selected source/filter and crop independently. A chip tap, sheet handoff or activity restoration can resume that same target only after a clean prior join. Source loss, failed suspension, explicit Stop or load replacement ends the reference: iOS never chooses another window, runs a capture tool or retries an ended observation. Selecting a replacement is an explicit agent action.

`LiveDisplayView` keys its task by the exact display, session, profile, scene and managed presentation activity. Only a decoded frame's validated dimensions cross the existing floating host communication seam, fenced by source, session, profile, surface and producer-scoped activity generation. A remounted renderer has a new producer identity; its local activity counter is not ordered against a retired renderer's counter. Body rendering checks the current source and managed activity synchronously, before task cleanup can clear old images or failures. Waiting/unchanged polls retain the last geometry for that exact source; source retirement publishes nil geometry so a replacement cannot inherit stale pixels or sizing. `LiveViewingActivity` binds a noninteractive native view to its exact `UIWindowScene`. That host belongs to one stable layout container outside the loading/image/error branches; publishing a frame or terminal fallback must not remount the detector, change its activity generation, or reopen the lease. A transparent `Group` is not a stable owner for this background representable. Application and that scene's native activation notifications own the generation fence, including inactive/active transitions coalesced by SwiftUI. The environment phase directly gates task admission and rendering; it must not also increment that native generation in an `onChange` callback. That feedback changes the same task ID twice for one phase transition. A rapid resume after DELETE can then hit SwiftUI's per-frame update limit, suppressing the final task while the newer generation rejects its predecessor. No phase callback, copied phase flag or delayed restart participates in this lifecycle. Admission and every post-await publication require that generation, current native application/scene activity, the mutable managed-surface owner, cancellation, exact surface generation, profile and latest-request nonce. There is no arbitrary connected-scene lookup or reliance solely on SwiftUI task cancellation timing. Dismissal, coverage, backgrounding and profile/session replacement retire presentation work. `LiveLease` carries the **original** origin/credential and owns one joined, cancellation-independent DELETE task. Cancellation initiates cleanup without waiting for an in-flight native decode to finish; duplicate closes join it and late frame responses are rejected. Changing profiles cannot strand cleanup or send the old lease to a new Gateway. The live transport follows no redirects. Same-origin WebSocket reconnects intentionally do not replace an independent HTTP viewer lease (`sameProfileReconnectKeepsLease`). Pairing creates a fresh profile ID; explicit profile transitions, including a same-ID switch, run lifecycle presentation retirement before connecting. Do not replace this with a blanket socket-epoch viewer fence: it would tear down healthy HTTP previews on ordinary socket recovery. Network/process loss still requires the Gateway's fifteen-second idle lease expiry (with up to one additional second for sweeping); no instantaneous remote cleanup is claimed offline.

Polling is sequential and capped at five requests per second. `X-Tron-Live-After` avoids retransmitting unchanged JPEGs; `waiting` clears previous-target pixels, while `unchanged` retains an already decoded frame. Ended observation is a terminal error rather than an automatic reconnect loop. Transient frame GET failures may make at most three attempts on the same lease, with three-second request deadlines and200/400ms delays; every await remains cancellation/closure fenced. Admission POSTs, invalid frames, source loss and ended references do not retry. Error envelopes contribute only an allowlisted live-failure classification, never raw server messages or arbitrary details. The viewer renders a safe reason rather than the model's alt/fallback prose. Native asynchronous start failures retain a bounded exact-reference reason on Gateway so that a successful initial POST cannot erase the later failure. Gateway also bounds the first-frame wait for each selected browser target and ends native first-frame waiting after10 seconds; a valid static frame may remain unchanged indefinitely while viewed, but successful capture setup without a first frame cannot renew a waiting lease forever. `LiveFrame` admits at most 2 MiB JPEG data, checks the encoded image's own dimensions against response metadata before decoding, then uses off-main, cancellation-fenced ImageIO preparation with a four-million-pixel, 2,560-edge and 16-million-decoded-byte limit. One app-wide `LiveImagePreparation` slot is shared by browser and native frames, including retired viewer generations: an already-running synchronous ImageIO call may drain after cancellation, but replacement candidates are dropped rather than queued or decoded concurrently. There is no image queue or artifact-cache insertion.

The typed descriptor contains no CDP URL, host path, browser port or input channel. Individual tool chips and grouped tool-sheet rows share `ToolDisplayActivation`; grouped custom activation waits for the outer managed sheet's completed dismissal and rechecks runtime, the model's current installation generation (not the old mounted tag), profile, application/scene activity and the selected tool's exact current display before publishing once. That source check uses the authoritative visible transcript, including admitted history pages rather than only the Gateway's bounded tail. Generic tools retain technical details. Provider-bound browser actions receive the same admitted display projection as explicit `display` results; commands with no exact binding cannot infer a browser from neighboring rows. Ordinary browser-tool diagnostics remain ordinary owner-authenticated tool output, not transport authority. Gateway owns only the read-only observer; browser automation continues independently. Child live-view handoff and native-daemon crash cleanup are not certified by this first-party feature. Focused coverage: `BrowserLiveViewingTests` checks original-profile cleanup, late open/frame fencing, capability, actual JPEG admission, non-cancellable preparation overlap and mixed browser/native lease frames using the production shared decode owner. Its kind-parameterized lease tests reject crossed capabilities/schemas and check original-profile cleanup and late open/frame fencing for both producers. `DisplayPresentationTests.nativeLiveDisplay` covers schema pairing, producer identity/geometry isolation and history/reconnect suppression; `SharedProtocolFixtureTests.nativeLiveSessionOpenAdmission` checks native session/cache projection and display-only transcript authority. `BrowserLiveMountedViewingTests.nativeRetirementDoesNotSelectReplacement` paints a native JPEG in both existing renderers, admits portrait geometry, retires on scene inactivity and checks terminal unavailability without selecting another window. Coverage/dismissal/profile/source regressions also exercise both kinds. `BrowserLiveMountedViewingTests` delivers successive actual JPEGs into the production sheet and floating renderers, requires advancing after-sequences with a single lease, and samples composited window pixels rather than treating a GET or permanent `waiting` response as proof of streaming. It also checks terminal decode failure without a reopen loop, painted floating-to-sheet lease handoff/reopen, polling/coverage, zero-area panel quiescence, dismissal, same-identity generation/profile replacement and joined lease/surface teardown even when the fixture throws. `DisplayPresentationTests` covers wire/surface/auto-presentation policy; Gateway regressions cover loader, lease and HTTP authority. `SessionSheetPresentationTests` exercises the actual mounted standalone/grouped control callbacks, outer managed-sheet dismissal before custom publication, same-runtime canonical replacement without changing installation, installation replacement retaining the exact selected result, and native browser-sheet chrome in both appearances. Its callback probe is compiled only for `HOSTED_TEST`, not application builds. The mounted browser fixture also posts native application/scene notifications with an unchanged SwiftUI phase to check lease retirement and same-source reopening. `coalescedNativeActivityReopens` posts inactive/active callbacks in one main-actor turn, requires a new painted lease, then delivers a different wide frame only to the covering sheet and verifies that geometry after replacing the higher-epoch renderer on return to floating. `floatingFrameGeometryAdaptsWithoutRemounting` resumes immediately after observing the original lease's DELETE: transport retirement is not a display-frame boundary, and the fixture must not add a frame delay to avoid task-ID feedback. It requires a second POST and advancing after-sequences on the new lease, not just two historical GETs. These are notification-callback and injected-phase tests, not actual OS backgrounding. These harnesses use injected transport and hosted `UIWindow`s; callback activation is not touch/VoiceOver automation and does not certify floating gestures, OS suspension or physical-device rendering.

The transcript decoder admits typed display metadata only on `toolResult` rows from `display`, or from `agent_browser` when its kind is `browser_live`. Gateway provider/call/session admission remains the authority; iOS does not promote raw `details` or verify ephemeral provider receipts. This rule applies at the enclosing transcript boundary, not just the descriptor decoder, so a valid browser action cannot invalidate `session.open`, live snapshots, or history/cache decode. `browser-tool-result-v4.json` is checked against Gateway's production message projection and decoded through `GatewaySessionOpenResponse` by `SharedProtocolFixtureTests`, then through chat projection to the exact floating tap route. Negative cases retain rejection of other tools/roles, non-live browser displays and malformed descriptors.

## Surfaces

The model requests a surface, but native policy resolves it by typed content kind and advertised eligibility:

- **Sheet** is the default and universal fallback. The running pill settles to a completed pill; an explicit tap opens the centrally routed `DisplaySheet`.
- **Inline** keeps the tool call's physical row identity. Its running pill and collapsed result share the normal left transcript edge. Textual content expands into a nearly full-width, rounded lavender Liquid Glass container with an adaptive bounded viewport and no nested transcript scroll. Images instead use a left-aligned 1.7× photo chip with an emerald loading spinner, an inset close control, and a color-scheme-adaptive backing for transparent pixels; tapping the photo opens the canonical photo sheet and closing morphs back to the tool pill. One measured row host keeps both endpoints mounted without any clipping surface. Collapse first fades the card and its native shadow at the expanded height, then contracts the already-invisible card region into the visible pill; expansion grows and crossfades in one transaction. The stable host prevents structural rerender glitches while preserving the same natural rounded Liquid Glass shadow as a user-message bubble. Disclosure state reaches its stable endpoint synchronously; backgrounding, presentation coverage, route removal, and retained resume therefore cannot inherit an in-flight logical phase. While the transcript is positioning, an expanded display keeps a bounded kind-specific placeholder and does not mount its asynchronous artifact renderer; adaptive content begins only after the opening reveal and physical tail lease have fully settled, when native pinned anchoring owns subsequent height changes. Public web, HLS, generic documents, and interactive HTML do not become inline scroll children.
- **Floating** keeps the completed pill and may publish one session-local overlay after an eligible live completion. The panel is one rounded Liquid Glass window without a solid header bar. The glass handle, close, and expand buttons keep their existing appearance and 44-point accessibility targets. Handle dragging tracks directly, projects release velocity and docks with a non-overshooting smooth animation. One native layout proposal, below the navigation toolbar and above the complete composer, owns every bound. The overlay is inside the composer's `safeAreaInset` modifier, not inside its content closure: UIKit/SwiftUI already accounts for the keyboard, multiline editor, photo/skill chips and resource picker. No copied composer height, additional keyboard observer or manual safe-area subtraction participates. Layout changes follow that existing structural/native clock without a geometry-to-state feedback loop. Each exact window owns one persistent normalized placement anchor and a transient grab point. A native pan recognizer updates that anchor directly in the same bounds coordinate space; its terminal callbacks project velocity and dock from the current position. No automatically resetting gesture offset contributes to rendering, so release cannot expose the pre-drag anchor. The grab point is measured in the touched window's coordinates so interrupting a dock starts at its visible location, not the old animation target. Cancellation settles once without momentum. Bottom docking follows the composer in both directions, constrained axes retain their placement preference, and retired gestures cannot move a successor. All content kinds fit the available region. Browser and native live images remain aspect-fit; very short windows may letterbox to preserve all three full-size glass controls rather than replacing or scaling them. If even those controls cannot fit, the route and placement remain selected but no hidden renderer runs. Floating unavailable text is centered directly on the window, without a nested info card. It is recoverable by tapping the canonical pill and is not a second `UIWindow` or system Picture in Picture.

Unsupported requested surfaces deterministically fall back to sheet. Audio/video larger than 50 MiB cannot trigger automatic inline or floating download; when floating was requested, an explicit user tap may open the bounded staged-file panel. The agent cannot choose dimensions, coordinates, z-order, autoplay, permissions, or whether close controls exist.

## Ownership and lifecycle

`ChatTranscriptProjectionKernel` keeps a display invocation in an isolated one-tool run so generic neighboring tools never morph with it. `ChatToolDescriptor` carries the strictly decoded display projection and the bounded requested surface needed by the running pill. Live-to-canonical reconciliation retains the tool-call physical identity and canonical result wins.

`ChatRoutes` owns the display sheet. `ChatSessionPresentation` owns only disposable selected-sheet, one floating route, one deferred floating route, and a bounded auto-presentation identity ledger (artifact revision or exact live producer/view/generation). `ChatFloatingDisplayHost` is mounted over the chat content surface rather than inside the transcript scroll view. Its exact-route `FloatingDisplayWindow` owns placement, transient drag state and one bounded preferred frame geometry; usable bounds come directly from native layout. The native-size grab offset and global touch position determine placement during a drag, including image/container resizing, subject to safe-bound clamping. The first grab cancels any existing dock in the same transaction; losing the mounted panel retires the gesture. Control minima letterbox extreme ratios rather than stretching pixels or expanding beyond the preferred width. `ChatFloatingDisplayLayoutTests` mounts the actual `ChatView` and compares native panel, navigation-bar and complete-composer frames. It exercises corner and scripted production pan callbacks, viewport contraction/restoration, a genuine hosted keyboard, combined photo/skill chips and multiline growth. Native-frame assertions cover direct tracking, the first release frames, intermediate edge docking, interruption/cancellation, keyboard/accessory movement and retained native window identity. Scripted pan samples do not certify the platform's physical-touch delivery. `BrowserLiveMountedViewingTests` independently checks painted-image/lease continuity across nonzero resizing, adaptive portrait/wide frame geometry, resize-during-drag continuity, retired placement callbacks, and centered popped-out/fallback content. These are hosted native geometry/callback and injected transport tests, not physical-device touch-drag or frame-rate certification. Closing, dragging, collapsing, and maximizing do not mutate Gateway or JSONL.

A floating panel appears automatically only for a completion added after the current installed-transcript baseline while the exact chat is ready, foreground-active, presentation publication is allowed, and no panel is already user-owned. The baseline resets rather than publishing when history or reconnect installs a transcript, so cache installation, foreground restoration, and background completion retain only the pill. A covering descendant may defer one candidate; route retirement clears all display presentation state.

## Rendering and security

Every display includes alt/fallback text and every renderer publishes that description to accessibility. Artifact requests use the selected profile plus exact session and opaque artifact identity. Markdown, text, code, PDF, and document sheets reuse `AttachmentFilePreviewSheet` and its `TronDocumentSheet` chrome while preserving the display's authored title. Document content leaves its background transparent so the native sheet material matches other standard sheets in both appearances; PDF pages retain their paper color, but their surrounding viewport is clear. The concrete document scroll owner supplies the custom top blur; native navigation and bottom-toolbar backgrounds stay hidden instead of adding solid bars. The same transparent shell applies to question/form, terminal, and unavailable-queue sheets (terminal/media content retains its own rendering). Image sheets reuse the exact historical photo-chip sheet—including its medium detent, concentric viewport, native pinch/double-tap zoom, overlay title, and glass confirmation control—while loading through `ChatMediaLoader`; local photo chips keep the thumbnail only as immediate presentation input and propagate the decoded full-resolution replacement into the mounted zoom view instead of trapping that thumbnail in sheet-local state. Inline images keep their bounded transcript renderer. Its readiness/activity-keyed task owns the request generation: no separate change observer may invalidate a newly admitted load without admitting its successor. Image, text, code, PDF, and HTML artifact publication recheck cancellation, generation, exact media identity, transcript readiness, and presentation activity after awaiting the loader, and a completed preparation for the exact source stays mounted across coverage rather than re-fetching and re-decoding. Cancellation of the view task stays silent; cancellation from a dependency while the request remains current ends in the unavailable-image state rather than an endless spinner. `SessionSheetPresentationTests.testInlinePhotoLoadsAfterReadinessAndResumeWithoutAnotherSheet` holds the real thumbnail HTTP response across readiness, resume, and combined transitions, then requires the native spinner to retire without opening another surface; it also covers dependency cancellation. Inline PDFs and bounded text also reuse existing native preview preparation, while unsupported generic documents stay sheet-only. Local audio/video is downloaded through the authenticated bounded file transport, validated against its advertised size, played from protected temporary storage without autoplay, and discarded on cancellation or teardown. Public webpage/HLS descriptors reject credentials, query/fragment persistence, private/reserved literals, and local DNS suffixes, then open as full-height, full-bleed `SFSafariViewController` sheets with one collapsible native browser bar and no duplicate Tron navigation chrome. Safari's close control dismisses the owning sheet, and Gateway credentials are never attached to remote redirects, playlists, segments, or keys.

Generated HTML uses the shared blue document title/Done and custom top blur, with WebKit's native top scroll-edge effect hidden so it cannot add a hard cutoff or dividing line. `SessionSheetPresentationTests.testHTMLDocumentUsesOnlyCustomTopBlur` mounts and scrolls real HTML in both appearances and verifies the single blur owner and retained sandbox settings. Generated HTML uses a nonpersistent `WKWebView`, disabled JavaScript, no base URL or file access, user-action media policy, blocked popup creation, navigation restricted to `about`, and a strict CSP that disables network, forms, frames, and script. SVG is classified with active HTML rather than inert image decoding. Renderer failure preserves the canonical fallback instead of hiding the transcript item.

Inline rendering is lazy and bounded. Text/PDF payloads retain the existing 25 MiB encoded boundary and preparation limits. Images cap decoded dimensions through `ChatMediaLoader`. Media teardown pauses and clears AVFoundation state before deleting its staged file. Floating content is session-local and is retired on background or route teardown.

## Accessibility

Display pills remain one compact control with their destination in the accessibility label. Inline content has separate 44-point collapse and optional sheet controls. Floating panels expose close/maximize controls and named corner movement actions so drag is never the only input. Agent-opened floating content does not intentionally move VoiceOver focus. Reduce Motion uses short fades for window insertion/removal and immediate docking rather than scale or travel animations; keyboard and composer layout remain with their existing native owners.
